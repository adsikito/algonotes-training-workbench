# 共享训练写入权限与事务约定

本应用保持 Sites 原有“仅所有者”访问范围。Sites 私有网关先验证浏览者或 `OAI-Sites-Authorization` 服务凭据，然后才将请求交给 Worker。服务凭据不转化为访客身份，因此 `/api/coach` 不要求额外的浏览者会话；令牌只放请求头，不进入代码、日志或笔记。

`Origin` 检查只用于限制跨站写入，**不是身份认证**。固定站点 hostname 检查只用于约束部署环境，也不是身份认证。应用依赖托管平台的私有访问边界；不能将此路由直接迁移到公开 Worker。更改站点访问范围或脱离 Sites 部署之前，必须增加独立的应用级写入策略。私人文件与笔记仍必须使用 `actor()`，教练接口只允许共享目录，不返回私人记录。

MCP 的认证由 Sites 平台进行，平台在转发时附加已验证的站点用户信息。工具输出仍只含共享训练内容。原自动推送可继续使用 Sites 支持的私有服务令牌，不需要部署代码才能写一份题单。

内容更新先预览，随后按稳定 batchId 原样应用。新增事务实现将所有共享记录、历史、操作回执与批次完成回执放在同一 D1 batch 中；任何版本冲突使整批回滚。并发重复相同批次回读已应用回执；不同内容不能复用批次ID。限制每批80项/4MiB，避免大事务占满内存。旧版本已完成回执仍可回读；旧版本部分写入需要先回读目录并重新预览，不能伪称已完成。

依据：Sites 1.1.2 `references/identity-and-secrets.md` 与 `references/site-mcp-server.md`，本轮实际核验。此说明不声称已对托管网关进行渗透测试。
